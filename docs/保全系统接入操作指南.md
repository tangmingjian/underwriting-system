# 核保引擎通用化 — 保全系统接入操作指南

## 1. 架构概览

```
┌─────────────────────┐  ┌─────────────────────┐
│ engine-feature       │  │ engine-rule          │
│ ContextNode          │  │ RuleEvaluator        │
│ FeatureCalcHandler   │  │ ConditionListEval    │
│ FeatureExtractionEng │  │ CrossDecisionTableEv │
│ FeatureResultDispat  │  │ ScorecardEvaluator   │
│ FeatureTargeting     │  │ RuleEngineFactory    │
│ FeatureDependencyRes │  │ WordingResolver      │
│ CacheOps / Groovy    │  │ OperatorHandler(SPI) │
│ 服务发现 / HTTP客户端  │  └─────────────────────┘
└─────────────────────┘           ↑
         ↑                按需引用（可选）
         │ 依赖
┌────────┴────────┐
│  核保系统        │        │  保全系统          │
│  Order/Policy   │        │  Endorsement       │
│  ContextImpl    │        │  ContextImpl       │
└─────────────────┘        └────────────────────┘
```

- `underwriting-engine-feature` — 特征取数（必选）
- `underwriting-engine-rule` — 规则评估（可选，需要核保时才引入）
- 两个 jar 包互不依赖，package 前缀均为 `com.insurance.uw.engine.core`
- JDK 11 / Spring Boot 2.7.18

保全系统只需做三件事：
1. **引入 jar** + 实现 `ContextNode` 接口
2. **实现 Repository**（或复用 MyBatis / 自建数据源）
3. **组装 Bean** 并调用 `FeatureExtractionEngine.extract()`

`engine-feature` 传递依赖：Spring Context、Jackson、MyBatis-Plus（optional）、Redis（optional）、Groovy（optional）、Caffeine（optional）。

> 标记为 `<optional>true</optional>` 的依赖如果保全系统不需要可以排除。

## 3. 第二步：实现 ContextNode（上下文树）

### 3.1 确定保全的层级结构

假设备全系统的业务模型是 **2 层树**：

```
EndorsementContext (root, levelName="ORDER")              ← 批改申请单
  └── EndorsementInsuredContext (levelName="INSURED") × N  ← 被保人
```

> **关键**：`levelName()` 返回值必须是 `"ORDER"`, `"POLICY"`, `"APPLICANT"`, `"INSURED"` 之一，与数据库 `t_feature_config` 表中的 `aggregation` / `storage_level` 字段值精确匹配。

### 3.2 编写 EndorsementContext（根节点）

```java
package com.endorsement.context;

import com.insurance.uw.engine.core.context.ContextNode;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
import java.util.stream.Collectors;

public class EndorsementContext implements ContextNode {

    private final Endorsement endorsement;
    private final List<EndorsementInsuredContext> children;
    private final Map<String, Object> featureStore = new ConcurrentHashMap<>();

    public EndorsementContext(Endorsement endorsement) {
        this.endorsement = endorsement;
        this.children = endorsement.getInsureds().stream()
                .map(ins -> new EndorsementInsuredContext(ins, this))
                .collect(Collectors.toList());
    }

    @Override public String getNodeId()           { return endorsement.getEndorsementId(); }
    @Override public String getLevelName()        { return "ORDER"; }
    @Override public ContextNode getParent()      { return null; }
    @Override public List<? extends ContextNode> getChildren() { return children; }
    @Override public Map<String, Object> getFeatureStore()    { return featureStore; }
    @Override public Object getEntity()           { return endorsement; }

    public Endorsement getEndorsement() { return endorsement; }
}
```

### 3.3 编写 EndorsementInsuredContext（叶子节点）

```java
package com.endorsement.context;

import com.insurance.uw.engine.core.context.ContextNode;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;

public class EndorsementInsuredContext implements ContextNode {

    private final EndorsementInsured insured;
    private final EndorsementContext parent;
    private final Map<String, Object> featureStore = new ConcurrentHashMap<>();

    public EndorsementInsuredContext(EndorsementInsured insured, EndorsementContext parent) {
        this.insured = insured;
        this.parent = parent;
    }

    @Override public String getNodeId()           { return insured.getInsuredId(); }
    @Override public String getLevelName()        { return "INSURED"; }
    @Override public ContextNode getParent()      { return parent; }
    @Override public List<? extends ContextNode> getChildren() { return Collections.emptyList(); }
    @Override public Map<String, Object> getFeatureStore()    { return featureStore; }
    @Override public Object getEntity()           { return insured; }

    // 代理属性（方便 Groovy 脚本访问）
    public String getIdNo()    { return insured.getIdNo(); }
    public String getName()    { return insured.getName(); }
    public int    getAge()     { return insured.getAge(); }
    public String getGender()  { return insured.getGender(); }
}
```

## 4. 第三步：复用现有的数据库特征 & 规则（关键）

### 4.1 数据是共享的，不是复制的

现有 `t_feature_config`、`t_feature_script`、`t_underwriting_rule` 表已经存有配置和脚本，保全系统**直接连同一数据库即可复用**，无需重新录入。

### 4.2 如何让现有特征对保全生效

**场景 A — 特征不需要修改（如信用评分 `ins.creditScore`）**：

现有特征配置已经是 `aggregation=ORDER, storageLevel=INSURED`，引擎在保全的 2 层树上运行：
- ORDER 层：用 `EndorsementContext` 作为 ctx 执行（聚合所有被保人）
- 结果按 `storageLevel=INSURED` 向下分发到 `EndorsementInsuredContext`
- **零改动即可复用**

**场景 B — 需要新增保全专用特征**：

直接在 `t_feature_config` 中 INSERT 新记录即可：

```sql
-- PARAM_MAPPING：从保全实体直读字段
INSERT INTO t_feature_config (
    feature_code, feature_name, calc_type, calc_config,
    aggregation, storage_level, version, ttl_seconds, status
) VALUES (
    'endorsement.changeReason', '保全变更原因', 'PARAM_MAPPING',
    '{"source":"order.changeReason"}',
    'ORDER', 'ORDER', 1, -1, 'ACTIVE'
);

-- EXTERNAL_API：调用外部服务（需要配合 Groovy 脚本）
INSERT INTO t_feature_config (
    feature_code, feature_name, calc_type, calc_config,
    aggregation, storage_level, version, ttl_seconds, status
) VALUES (
    'ins.endorsementRisk', '保全风险评分', 'EXTERNAL_API',
    '{"service":{"discovery_type":"DIRECT","path":"https://xxx/risk","method":"POST","timeout_ms":3000},"input_script_id":"buildEndorsementReq","output_script_id":"extractEndorsementRisk"}',
    'ORDER', 'INSURED', 1, 300, 'ACTIVE'
);
```

### 4.3 Groovy 脚本注意事项

现有 Groovy 脚本中的 `buildRequest(OrderFeatureContext ctx)` 签名使用了核保的具体类型。在保全系统中，脚本接收到的 ctx 是保全的 ContextNode 实现类（如 `EndorsementContext`），不是 `OrderFeatureContext`。

两种处理方式：

**方式 A — 修改脚本签名为通用 Object（推荐）**：
```groovy
Map buildRequest(Object ctx) {
    // ctx instanceof ContextNode → true
    // 通过 ctx.getChildren() / ctx.getEntity() 访问数据
    ...
}
```

**方式 B — 保全系统新建专用脚本**：
```sql
INSERT INTO t_feature_script (script_id, script_name, script_type, script_text, version, status)
VALUES ('buildEndorsementReq', '保全风险-入参', 'INPUT',
'Map buildRequest(EndorsementContext ctx) {
    // 直接引用保全类型
    ...
}', 1, 'ACTIVE');
```

### 4.4 核保规则复用

现有规则（`t_underwriting_rule`）是按 `product_code` + `rule_type` 匹配的：
- 如果保全产品需要同一规则，无需改动，`RuleApplicationService.evaluate()` 会按 `RuleType` 在 ContextNode 树上匹配对应层级
- 如果保全产品需要不同规则，INSERT 新规则并指定 `product_code` 为保全产品码

### 4.5 自定义操作符（SPI）

`ConditionListEvaluator` 支持 12 种内置操作符（EQ、GT、IN、BETWEEN 等）。如需扩展或覆盖，实现 `OperatorHandler` 并标注 `@Component`：

```java
import com.insurance.uw.engine.core.rule.engine.OperatorHandler;

@Component
public class MyOperatorHandler implements OperatorHandler {
    @Override
    public boolean supports(String operator) {
        return "MY_CUSTOM_OP".equals(operator);       // 新增操作符
        // 或 return "EQ".equals(operator);           // 覆盖内置 EQ
    }

    @Override
    public boolean compare(Object featureValue, String operator, Object configValue) {
        // 自定义比较逻辑
        return ...;
    }
}
```

## 5. 第四步：实现 Repository 接口

Repository 接口在各自模块中：

| 接口 | 所在 jar | 用途 | 必须实现？ |
|------|----------|------|-----------|
| `FeatureConfigRepository` | engine-feature | 加载特征配置 | **是** |
| `FeatureScriptRepository` | engine-feature | 加载 Groovy 脚本 | 如有 EXPRESSION/EXTERNAL_API 类型特征是 |
| `UnderwritingRuleRepository` | engine-rule | 加载规则 | 如需规则评估则是 |
| `CrossDecisionTableRepository` | engine-rule | 交叉决策表 | 如有交叉表规则才是 |
| `ScorecardConfigRepository` | engine-rule | 评分卡 | 如有评分卡规则才是 |

### 方式 A — 复用核保的 MyBatis 实现（两系统连同一个库）

直接从 `underwriting-infrastructure` 引入实现类即可。

### 方式 B — 自建实现（保全独立数据库）

## 6. 第五步：组装 Bean 并调用引擎

### 6.1 Spring Configuration

```java
@Configuration
public class EndorsementEngineConfig {

    // ===== Repository =====
    @Bean
    public FeatureConfigRepository featureConfigRepository(
            FeatureConfigMapper mapper, CacheOps cacheOps) {
        return new FeatureConfigRepositoryImpl(mapper, cacheOps, Duration.ofMinutes(10));
    }

    @Bean
    public FeatureScriptRepository featureScriptRepository(
            FeatureScriptMapper mapper, CacheOps cacheOps) {
        return new FeatureScriptRepositoryImpl(mapper, cacheOps, Duration.ofMinutes(10));
    }

    // ===== 缓存 =====
    @Bean
    public CacheOps cacheOps(StringRedisTemplate redis) {
        return new CacheOps(redis, new ObjectMapper()
                .registerModule(new JavaTimeModule())
                .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS));
    }

    @Bean
    public FeatureResultCache featureResultCache(CacheOps cacheOps) {
        return new RedisFeatureResultCache(cacheOps);
    }

    // ===== Groovy 引擎 =====
    @Bean

        return new GroovyMappingEngineImpl();
    }

    // ===== 服务发现 =====
    @Bean
    public ServiceDiscoveryRouter serviceDiscoveryRouter(List<ServiceDiscoveryStrategy> strategies) {
        return new ServiceDiscoveryRouter(strategies);
    }

    // ===== HTTP 客户端 =====
    @Bean
    public DownstreamApiClient downstreamApiClient(
            RestTemplate restTemplate, ServiceDiscoveryRouter router,
            CircuitBreaker circuitBreaker) {
        return new DownstreamApiClientImpl(restTemplate, router, circuitBreaker);
    }

    public ExecutorService featureExecutor() {
        return new ThreadPoolExecutor(4, 8, 60, TimeUnit.SECONDS,
                new LinkedBlockingQueue<>(200),
                new ThreadPoolExecutor.CallerRunsPolicy());

    // ===== Handler ====

        return new CustomCalcHandler(customHandlers);
```

### 6.2 调用示例

```java
@Service
public class EndorsementFeatureService {

    @Autowired
    private FeatureExtractionEngine engine;

    public void evaluateEndorsement(Endorsement endorsement) {

        // 1. 构建 ContextNode 树
        EndorsementContext rootCtx = new EndorsementContext(endorsement);

        // 2. 确定需要的特征码
        Set<String> featureCodes = Set.of("ins.creditScore", "ins.age", "endorsement.changeReason");

        // 3. 构建 FeatureTargeting 输入映射
        FeatureTargeting targeting = new FeatureTargeting();
        Map<String, Map<String, Set<String>>> inputMap = new HashMap<>();
        inputMap.put(
            FeatureTargeting.pathKey("ORDER", rootCtx.getNodeId()),
            rootCtx.getChildren().stream().collect(Collectors.toMap(
                ins -> FeatureTargeting.pathKey("INSURED", ins.getNodeId()),
                ins -> featureCodes
            ))
        );
        targeting.setInputMap(inputMap);

        // 4. 执行特征提取（结果直接写入 ContextNode 树）
        engine.extract(rootCtx, featureCodes, targeting);

        // 5. 从树中读取结果
        Map<String, Object> orderFeatures = rootCtx.getFeatureStore();
        for (EndorsementInsuredContext insCtx : rootCtx.getChildren()) {
            Map<String, Object> allFeatures = insCtx.collectFeaturesUpward();
            System.out.println("被保人 " + insCtx.getNodeId() + " 特征: " + allFeatures);
        }
    }
}
```

## 9. 关键约定速查

| 约定 | 说明 |
|------|------|
| `getLevelName()` 返回值 | 必须与 `AggregationLevel` 枚举名一致：`"ORDER"` `"POLICY"` `"APPLICANT"` `"INSURED"` |
| `getNodeId()` 返回值 | 叶子节点的业务 ID（如 insuredId），用于分发匹配 |
| `getFeatureStore()` | 必须返回**可变 Map**（如 `ConcurrentHashMap`），引擎直接 put |
| `getEntity()` | 返回原始领域对象，`PARAM_MAPPING` 通过反射读 getter |
| 树结构 | 根节点只有一个，叶子节点 N 个。中间层级（如 POLICY）如不需要可省略 |
| FeatureTargeting 的 pathKey | 格式 `"levelName:entityId"`，如 `"ORDER:E001"`, `"INSURED:I001"` |
| 自定义操作符 | 实现 `OperatorHandler` + `@Component`，自动注入 `ConditionListEvaluator` |
| 环境要求 | JDK 11+, Spring Boot 2.7.x |
