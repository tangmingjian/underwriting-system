# 核保引擎通用化 — 保全系统接入操作指南

## 1. 架构概览

```
┌────────────────────────────────────────────────┐
│               underwriting-engine-core          │
│  ContextNode / FeatureCalcHandler / Engine      │
│  FeatureResultDispatcher / FeatureTargeting     │
│  FeatureDependencyResolver / RuleEngineFactory  │
│  CacheOps / GroovyMappingEngine ...             │
└──────────────┬─────────────────────────────────┘
               │ 依赖（引入 jar）
       ┌───────┴───────┐
       ▼               ▼
┌──────────────┐ ┌──────────────┐
│  核保系统     │ │  保全系统     │
│  Order/Polic │ │  Endorsement │
│  ContextImpl │ │  ContextImpl │
└──────────────┘ └──────────────┘
```

引擎核心（`underwriting-engine-core`）已与核保领域解耦，保全系统只需做三件事：
1. **引入 jar** + 实现 `ContextNode` 接口
2. **实现 Repository**（或复用 MyBatis / 自建数据源）
3. **组装 Bean** 并调用 `FeatureExtractionEngine.extract()`

## 2. 第一步：引入 Maven 依赖

```xml
<dependency>
    <groupId>com.insurance.uw</groupId>

```

传递依赖包括：Spring Context、Jackson、MyBatis-Plus、Groovy、Caffeine、Redis 等。标记为 `<optional>true` 的依赖（如 MyBatis、Redis）如果保全系统不用可按需排除。

## 3. 第二步：实现 ContextNode（上下文树）

### 3.1 确定保全的层级结构

假设备全系统的业务模型是 **2 层树**：

```
EndorsementContext (root, levelName="ORDER")        ← 批改申请单
  └── EndorsementInsuredContext (levelName="INSURED") × N   ← 被保人
```

> **关键**：`levelName()` 返回值必须是 `"ORDER"`, `"POLICY"`, `"APPLICANT"`, `"INSURED"` 之一，与数据库 `t_feature_config` 表中的 `aggregation` / `storage_level` 字段值精确匹配。

### 3.2 编写 EndorsementContext（根节点）

```java
package com.endorsement.context;

import com.insurance.uw.engine.core.context.ContextNode;

public class EndorsementContext implements ContextNode {

    private final Endorsement endorsement;           // 保全领域实体
    private final List<EndorsementInsuredContext> children;
    private final Map<String, Object> featureStore = new ConcurrentHashMap<>();

    public EndorsementContext(Endorsement endorsement) {
        this.endorsement = endorsement;
        this.children = endorsement.getInsureds().stream()
                .map(ins -> new EndorsementInsuredContext(ins, this))
                .collect(Collectors.toList());
    }

    // ===== ContextNode 接口实现 =====

    @Override
    public String getNodeId() {
        return endorsement.getEndorsementId();       // 业务 ID
    }

    @Override
    public String getLevelName() {
        return "ORDER";                              // 顶层 → ORDER
    }

    @Override
    public ContextNode getParent() {
        return null;                                 // 根节点无父
    }

    @Override
    public List<? extends ContextNode> getChildren() {
        return children;
    }

    @Override
    public Map<String, Object> getFeatureStore() {
        return featureStore;                         // 引擎写入的特征结果
    }

    @Override
    public Object getEntity() {
        return endorsement;                          // 供 ParamMapping 反射取值
    }

    // ===== 业务便捷方法 =====
    public Endorsement getEndorsement() { return endorsement; }
}
```

### 3.3 编写 EndorsementInsuredContext（叶子节点）

```java
package com.endorsement.context;

import com.insurance.uw.engine.core.context.ContextNode;

public class EndorsementInsuredContext implements ContextNode {

    private final EndorsementInsured insured;
    private final EndorsementContext parent;
    private final Map<String, Object> featureStore = new ConcurrentHashMap<>();

    public EndorsementInsuredContext(EndorsementInsured insured, EndorsementContext parent) {
        this.insured = insured;
        this.parent = parent;
    }

    @Override
    public String getNodeId() {
        return insured.getInsuredId();
    }

    @Override
    public String getLevelName() {
        return "INSURED";                            // 叶子层级
    }

    @Override
    public ContextNode getParent() {
        return parent;
    }

    @Override
    public List<? extends ContextNode> getChildren() {
        return List.of();                            // 叶子节点
    }

    @Override
    public Map<String, Object> getFeatureStore() {
        return featureStore;
    }

    @Override
    public Object getEntity() {
        return insured;                              // 供 ParamMapping 反射取值
    }

    // ===== 代理属性（方便 Groovy 脚本访问） =====
    public String getIdNo()    { return insured.getIdNo(); }
    public String getName()    { return insured.getName(); }
    public int    getAge()     { return insured.getAge(); }
    public String getGender()  { return insured.getGender(); }
}
```

## 4. 第三步：复用现有的数据库特征&规则（关键）

### 4.1 数据是共享的，不是复制的

现有 `t_feature_config`、`t_feature_script`、`t_underwriting_rule` 表已经存有配置和脚本，保全系统**直接连同一数据库即可复用**，无需重新录入。

### 4.2 如何让现有特征对保全生效

**场景 A — 特征不需要修改（如信用评分 `ins.creditScore`）**：

现有特征配置已经是 `aggregation=ORDER, storageLevel=INSURED`，引擎在保全的 2 层树上运行：
- ORDER 层：用 `EndorsementContext` 作为 ctx 执行（聚合所有被保人）
- 结果按 `storageLevel=INSURED` 向下分发到 `EndorsementInsuredContext`
- **零改动即可复用**

**场景 B — 需要新增保全专用特征**：

直接在 `t_feature_config` 中 INSERT 新记录即可：

```sql
-- 新增保全专用的 PARAM_MAPPING 特征：直接从保全实体取值
INSERT INTO t_feature_config (
    feature_code, feature_name, category, data_type, calc_type,
    calc_config, aggregation, storage_level, version, ttl_seconds, status
) VALUES (
    'endorsement.changeReason', '保全变更原因', 'ATOMIC', 'STRING', 'PARAM_MAPPING',
    '{"source":"order.changeReason"}',    -- 从根节点 entity 反射取值
    'ORDER', 'ORDER', 1, -1, 'ACTIVE'
);

-- 新增保全专用的 EXTERNAL_API 特征（需要配合 Groovy 脚本）
INSERT INTO t_feature_config (
    feature_code, feature_name, category, data_type, calc_type,
    calc_config, aggregation, storage_level, version, ttl_seconds, status
) VALUES (
    'ins.endorsementRisk', '保全风险评分', 'ATOMIC', 'INT', 'EXTERNAL_API',
    '{"service":{"discovery_type":"DIRECT","path":"https://xxx/risk","method":"POST","timeout_ms":3000},"input_script_id":"buildEndorsementReq","output_script_id":"extractEndorsementRisk"}',
    'ORDER', 'INSURED', 1, 300, 'ACTIVE'
);
```

### 4.3 Groovy 脚本注意事项

现有 Groovy 脚本中的 `buildRequest(OrderFeatureContext ctx)` 签名使用了核保的具体类型。**在保全系统中，脚本接收到的 ctx 是保全的 ContextNode 实现类（如 `EndorsementContext`），不是 `OrderFeatureContext`。**

两种处理方式：

**方式 A — 修改脚本签名为通用 Object（推荐）**：
```groovy
// 改为 Object 类型，通过 ContextNode 接口导航
Map buildRequest(Object ctx) {
    // ctx instanceof ContextNode → true
    // 通过 ctx.getChildren() / ctx.getEntity() 访问数据
    ...
}
```

**方式 B — 保全系统新建专用脚本**：
```sql
INSERT INTO t_feature_script (script_id, script_name, script_type, script_text, version, status)
VALUES ('buildEndorsementReq', '保全风险-入参', 'INPUT',
'Map buildRequest(com.endorsement.context.EndorsementContext ctx) {
    // 直接引用保全类型
    ...
}', 1, 'ACTIVE');
```

### 4.4 核保规则复用

现有规则（`t_underwriting_rule`）是按 `product_code` + `rule_type` 匹配的：
- 如果保全产品需要同一规则，**无需任何改动**，规则引擎会按 `RuleType.INSURED` / `APPLICANT` 等在 ContextNode 树上匹配对应层级
- 如果保全产品需要不同规则，INSERT 新规则并指定 `product_code` 为保全产品码

```sql
-- 复用核保的信用评分规则（RULE_CREDIT_001），检查 feature_codes 是否满足保全需要
-- 如果满足：无需改动，规则自动生效
-- 如果不满足：新增一条保全专用规则

INSERT INTO t_underwriting_rule (
    rule_code, rule_name, rule_type, eval_type,
    expression, feature_codes, product_code, priority, status
) VALUES (
    'ENDORSE_CREDIT_001', '保全信用评分达标', 'INSURED', 'CONDITION_LIST',
    '{"logic":"AND","items":[{"feature":"ins.creditScore.score","operator":"GTE","value":600}]}',
    'ins.creditScore', 'ENDORSE_PRODUCT_001', 10, 1
);
```

## 5. 第四步：实现 Repository 接口

引擎需要的 Repository 接口定义在 `com.insurance.uw.engine.core.repository` 包中：

| 接口 | 用途 | 必须实现？ |
|------|------|-----------|
| `FeatureConfigRepository` | 加载特征配置 | **是** |
| `FeatureScriptRepository` | 加载 Groovy 脚本 | 如有 EXPRESSION/EXTERNAL_API 类型特征是 |
| `UnderwritingRuleRepository` | 加载规则 | 如需规则评估则是 |
| `CrossDecisionTableRepository` | 交叉决策表 | 如有交叉表规则才是 |
| `ScorecardConfigRepository` | 评分卡 | 如有评分卡规则才是 |

### 方式 A — 复用核保的 MyBatis 实现（两系统连同一个库）

直接从 `underwriting-infrastructure` 引入实现类即可，不需要自己写。

### 方式 B — 自建实现（保全独立数据库）

```java
@Repository
public class EndorsementFeatureConfigRepository implements FeatureConfigRepository {

    @Autowired
    private EndorsementFeatureConfigMapper mapper;  // 自己的 MyBatis Mapper

    @Override
    public Optional<FeatureConfig> findByFeatureCode(String code) {
        return Optional.ofNullable(mapper.selectByCode(code));
    }

    @Override
    public List<FeatureConfig> findByFeatureCodes(List<String> codes) {
        return mapper.selectByCodes(codes);
    }

    // ... 其他方法
}
```

## 6. 第五步：组装 Bean 并调用引擎

### 6.1 Spring Configuration

```java
@Configuration
public class EndorsementEngineConfig {

    // ===== Repository（以复用核保实现为例） =====
    @Bean
    public FeatureConfigRepository featureConfigRepository(
            FeatureConfigMapper mapper, CacheOps cacheOps,
            @Value("${underwriting.cache.feature-config-ttl:600}") Duration ttl) {
        return new FeatureConfigRepositoryImpl(mapper, cacheOps, ttl);
    }

    @Bean
    public FeatureScriptRepository featureScriptRepository(
            FeatureScriptMapper mapper, CacheOps cacheOps,
            @Value("${underwriting.cache.script-ttl:1800}") Duration ttl) {
        return new FeatureScriptRepositoryImpl(mapper, cacheOps, ttl);
    }

    // ===== Groovy 引擎 =====
    @Bean
    public GroovyMappingEngine groovyMappingEngine() {
        return new GroovyMappingEngineImpl();
    }

    // ===== 缓存 =====
    @Bean
    public CacheOps cacheOps(StringRedisTemplate redis, ObjectMapper mapper) {
        return new CacheOps(redis, mapper);
    }

    @Bean
    public FeatureResultCache featureResultCache(CacheOps cacheOps) {
        return new RedisFeatureResultCache(cacheOps);
    }

    // ===== 线程池 =====
    @Bean("endorsement-feature-executor")
    public ExecutorService featureExecutor() {
        return new ThreadPoolExecutor(4, 8, 60, TimeUnit.SECONDS,
                new LinkedBlockingQueue<>(200),
                new ThreadFactoryBuilder().setNamePrefix("endorsement-feature-").build());
    }

    // ===== Handler（按需注册） =====
    @Bean
    public ParamMappingCalcHandler paramMappingCalcHandler() {
        return new ParamMappingCalcHandler();
    }

    @Bean
    public ExpressionCalcHandler expressionCalcHandler(
            FeatureScriptRepository scriptRepo, GroovyMappingEngine engine) {
        return new ExpressionCalcHandler(scriptRepo, engine);
    }

    @Bean
    public ExternalApiCalcHandler externalApiCalcHandler(
            FeatureScriptRepository scriptRepo, GroovyMappingEngine engine,
            DownstreamApiClient apiClient) {
        return new ExternalApiCalcHandler(scriptRepo, engine, apiClient);
    }

    // 如有自定义 Java 实现的特征
    @Bean
    public CustomCalcHandler customCalcHandler(List<CustomFeatureHandler> customHandlers) {
        return new CustomCalcHandler(customHandlers);
    }

    // ===== 依赖解析器 =====
    @Bean
    public FeatureDependencyResolver dependencyResolver() {
        return new FeatureDependencyResolver();
    }

    // ===== 核心引擎 =====
    @Bean
    public FeatureExtractionEngine featureExtractionEngine(
            FeatureConfigRepository configRepo,
            FeatureDependencyResolver resolver,
            @Qualifier("endorsement-feature-executor") ExecutorService executor,
            List<FeatureCalcHandler> handlers,
            FeatureResultCache cache) {
        return new FeatureExtractionEngine(configRepo, resolver, executor, handlers, cache);
    }

    // ===== 规则引擎（可选） =====
    @Bean
    public RuleEngineFactory ruleEngineFactory(
            ConditionListEvaluator cle,
            CrossDecisionTableEvaluator cdte,
            ScorecardEvaluator se) {
        return new RuleEngineFactory(cle, cdte, se);
    }
}
```

### 6.2 调用示例

```java
@Service
public class EndorsementFeatureService {

    @Autowired
    private FeatureExtractionEngine engine;

    @Autowired
    private RuleEngineFactory ruleEngine;

    public void evaluateEndorsement(Endorsement endorsement) {

        // 1. 构建 ContextNode 树
        EndorsementContext rootCtx = new EndorsementContext(endorsement);

        // 2. 确定需要的特征码（可从规则推导，也可直接指定）
        Set<String> featureCodes = Set.of(
            "ins.creditScore",
            "ins.age",
            "ins.gender",
            "endorsement.changeReason"
        );

        // 3. 构建 FeatureTargeting 输入映射
        FeatureTargeting targeting = new FeatureTargeting();
        Map<String, Map<String, Set<String>>> inputMap = new HashMap<>();
        for (EndorsementInsuredContext insCtx : rootCtx.getChildren()) {
            inputMap
                .computeIfAbsent(
                    FeatureTargeting.pathKey("ORDER", rootCtx.getNodeId()),
                    k -> new HashMap<>())
                .put(
                    FeatureTargeting.pathKey("INSURED", insCtx.getNodeId()),
                    featureCodes
                );
        }
        targeting.setInputMap(inputMap);

        // 4. 执行特征提取（结果直接写入 ContextNode 树）
        engine.extract(rootCtx, featureCodes, targeting);

        // 5. 从树中读取结果
        Map<String, Object> orderFeatures = rootCtx.getFeatureStore();
        for (EndorsementInsuredContext insCtx : rootCtx.getChildren()) {
            Map<String, Object> insFeatures = insCtx.getFeatureStore();
            System.out.println("被保人 " + insCtx.getNodeId() + " 特征: " + insFeatures);
        }

        // 6. 规则评估
        Map<String, Object> flatFeatures = rootCtx.getFeatureStore();
        // 对每个被保人：
        for (EndorsementInsuredContext insCtx : rootCtx.getChildren()) {
            Map<String, Object> allFeatures = insCtx.collectFeaturesUpward();
            // allFeatures = orderFeatures + insuredFeatures（后者覆盖同名 key）
            boolean passed = ruleEngine.evaluate(EvalType.CONDITION_LIST, allFeatures, ruleExpression);
        }
    }
}
```

## 9. 关键约定速查

| 约定 | 说明 |
|------|------|
| `getLevelName()` 返回值 | 必须与 `AggregationLevel` 枚举名一致：`"ORDER"` / `"POLICY"` / `"APPLICANT"` / `"INSURED"` |
| `getNodeId()` 返回值 | 叶子节点的业务 ID（如 insuredId），用于分发匹配 |
| `getFeatureStore()` | 必须返回**可变 Map**（如 `ConcurrentHashMap`），引擎直接 put |
| `getEntity()` | 返回原始领域对象，`PARAM_MAPPING` 通过反射读 getter |
| 树结构 | 根节点只有一个，叶子节点 N 个。中间层级（如 POLICY）如不需要可省略 |
| FeatureTargeting 的 pathKey | 格式 `"levelName:entityId"`，如 `"ORDER:E001"`, `"INSURED:I001"` |
| 同人客户号 | 如果实体有 `customerNos` 字段，Groovy 脚本可自行处理同人合并逻辑 |
